# 0013. Bifrost state, config and keys

- Status: Accepted
- Date: 2026-10-22

## Context

ADR 0008 settled access, images and the Terraform shape for gateways, and put LiteLLM on Cloud SQL. Bifrost differs in three ways. It stores state in SQLite by default, and on Cloud Run that lives in the instance's memory. Its configuration can come from a file, from the stores (changed through the UI and API) or both. Its virtual keys can be declared in the file, so no key has to be minted after a deploy.

## Decision

- **Postgres on Cloud SQL for both the config store and the logs store.** Same instance shape as LiteLLM (`db-f1-micro`, Postgres 16, Cloud SQL socket, no VPC). SQLite would lose budget usage (test 3) and request logs (test 6) on every scale-to-zero. Bifrost's own Cloud Run guide says the same.
- **`config.json` is the source of truth** (`source_of_truth: config.json`). The file, held in a Secret Manager secret and copied into `APP_DIR` at start, wins over changes made in the UI, so a redeploy always returns to the committed setup.
- **Virtual keys are declared in the config and generated by Terraform**, one per caller (`agw-bifrost-agent-key`, `agw-bifrost-harness-key`). No key is minted by hand after a deploy. The admin password, setup token, encryption key and database password are generated the same way.
- **Prices are explicit** in `pricing_overrides` (ADR 0009).
- **`max_instances` stays 1,** as for LiteLLM.

## Consequences

- A destroy and redeploy gives the same config with new key values.
- Key values sit in Secret Manager and in the stack's Terraform state (private state bucket).
- Changes made in the UI to what the file sets (providers, virtual keys, prices, auth) are replaced at the next start; sections the file leaves out keep their database rows (to confirm in the tests). The UI is for looking, not changing.
- The database is stopped between sessions (`make stop-bifrost`), as for LiteLLM.
- Tests that need a different config use a window (ADR 0010).

## Alternatives considered

- **SQLite on the instance:** state lost on scale-to-zero.
- **`split` source of truth (the default):** the UI and file merge, so the running config could differ from the committed file.
- **Keys minted through the API after deploy (LiteLLM's way):** a manual step, and the key values would not be in Terraform.
- **Bifrost's Terraform module:** grants `allUsers` invoker and builds a VPC for GKE (the same objection as ADR 0008).
